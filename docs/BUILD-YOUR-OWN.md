# 从空目录搭建类似项目

顺序的目的，是让每一步都产生可运行反馈，同时晚一点再引入还没有被需求证明的复杂度。

## 1. 静态界面

**问题**：先确认信息架构，而不是先建后端。**做法**：用 React/Vite 做 Overview 骨架和响应式布局，数据先写固定 fixture。**为什么先做**：你会快速发现真正需要的字段。**最小验收**：桌面和平板能读懂四个核心指标。**常见错误**：把 fixture 结构当永久 API。**练习**：增加空状态和失败状态。

教程可把所有组件写一个文件；项目开始稳定后再按页面/共享组件拆分。大型设计系统还会有 tokens、Storybook 和可访问性回归。

## 2. 只读 ActivityWatch adapter

**约束**：原始数据不能被修改。建立 Express 和专用 `ActivityWatchClient`，只暴露需要的查询，不做通用代理。**为什么**：浏览器 CORS、API 变化和隐私边界集中在一处。**验收**：AW 在线返回状态，离线仍返回可理解错误。**错误**：写死电脑名或 bucket id。**练习**：动态发现第二台 host。

## 3. 共享 TypeScript 类型

为 API response 建 `shared/types.ts`。**为什么此时做**：数据已从 fixture 变成跨进程契约。**验收**：前后端改字段时编译器同时提示。**错误**：以为 TypeScript 能验证网络输入；服务端仍需 Zod。**练习**：给错误响应定义 discriminated union。

## 4. 纯数据聚合

把区间交集、分类、小时分桶放进不访问网络/文件的函数。**为什么**：时间边界最容易错，纯函数测试最快。**验收**：AFK、零时长、04:00、Sydney DST 都有测试。**错误**：用本机时区隐式解析 ISO。**练习**：实现跨日区间按实际秒数拆分。

## 5. 持久化与迁移

先用 JSON schema + 原子写盘 + 备份。**为什么不一开始上数据库**：需求尚未证明查询与并发成本。**验收**：不同 cwd/重启仍读同一文件，损坏时恢复备份，旧 schema 可迁移。**错误**：解析失败后把默认值写回，覆盖修复线索。**练习**：实现 revision 冲突。

## 6. 状态机

为番茄列出 Idle/Running/Paused/Completed 和合法边。**为什么先画再写**：按钮分支很容易漏掉重启与并发。**验收**：每条合法/非法边都有测试，暂停 interval 不计时。**错误**：每秒持久化剩余数字。**练习**：加入休息状态，但先明确取消/跳过语义。

## 7. 错误处理

区分输入错误 400、状态冲突 409、不存在 404、外部服务不可用 503。**为什么**：UI 才能决定“提示用户改输入”还是“稍后重试”。**验收**：AW 离线仍保存番茄为 pending。**错误**：所有异常都返回 500，或 catch 后静默成功。**练习**：为错误增加稳定 code，而非依赖英文 message。

## 8. 自动化测试

先单元，再 API，最后少量关键 E2E。**为什么**：测试越接近浏览器越真实也越慢。**验收**：状态机、迁移、隐私、并发和一条用户主流程被覆盖。**错误**：只验证 happy path 或只看 build 通过。**练习**：让 fake clock 测自动结束，不真实等待 25 分钟。

## 9. 生产启动

构建静态前端和 Node 服务，只监听 loopback，再用 Windows 计划任务启动。**为什么最后做**：先稳定运行契约，再固化部署。**验收**：`/api/health` 不依赖 AW；移动项目后可重装任务；日志不含标题。**错误**：用端口占用就判断“自己的服务已启动”。**练习**：加版本化 health response。

## 一条判断规则

每想增加一层，问三个问题：它隔离了哪种变化？谁负责维护它？删掉后会出现什么具体失败？答不出来时，可能暂时不需要这一层。反过来，当同一逻辑已复制三处、失败跨边界扩散或状态没有唯一所有者时，就应该抽层。
